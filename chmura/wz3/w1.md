### Storage w cloud
- daje możliwość wysokiego skalowania
- dostęp do danych po http
- dostęp z całego świata
- trwałość
- redundancja

### Sposoby przechowywania danych w storage cloud 
- LRS (3 kopie w 1 centrum danych)
- ZRS (3 kopie między 3 strefami dostępności w regionie (np. region to frankfurt ale tam kilka centrów danych), redundancja w strefie)
- GRS (3 kopie w regionie podstawowym i 3 kopie w regionie oddalonym)
- GeoZone Redundant Storage (połączenie ZRS i GRS 18 kopii na całym świecie)


### Tworzenie storage
- nazwa unikalna GLOBALNIE, a nie subskrybcji


### Storage type
- azure blob storage (ogromne ilosci danych nieustruktyryzowane, zdjecia, binarne itp uługa dostępna globalnie, możliwość hostowania statycznych stron internetowych),
- azure files (stansard -hdd, premium - ssd taka szybkość, można udostępniać zasoby za pomocą SMB (server messege block) lub nfs (network file system), montowania plików do vm, synchronizacja plików za pomocą Azure File Sync)
- other (tables and queues, Azure queue storage, duża ilość - miliony 64kB komunikatów, kolejkowanie danych, trwałość komuniatów, prosty interfejs REST || Azure Table Storage - dane bez schematu, klucz-wartość, ogromne zbiory danych,)

## Rodzaje blobów
- block blobs
- file shares
- page blobs - stronicowe, 512b pages, losowy odczyt i zapis, podstawa poid dyski wirtualne pod maszyny wirtualne
- append blobs - pod operacje dołączania, logowanie i audyty


Access tier - warstwy dostępu- optymalizacja kosztów jak często będziemy korzystać z danych
- hot - najdroższa, szybki dostęp "ssd"
- cool - wyższy czas dostępu, niższy koszt, dane conajmniej 30dni "hhd"
- cold - żadki dostęp na przykład backup, najniższy koszt przechowywania, opóźnienie do danych nawet do 1 dnia, dla danych odpytywanych nie częściej niż pół roku, do streamingów video, obrazy, dane analityczne


Wgranie danych do chmury bez problemu płatność tylko za storage, za migracje i odczyt trzeba płacić

### Konwencje nazewnictwa na Microsoft Azure
- Azure Naming Tool - automatyczne nazywanie zasobów
- nazywanie zasobów: typ zasobu np. rg,vm  rg-navigator-prod-001
- bezpieczeństwo - nazwa środowiska (dev. prod.)
- nazwa ma mieć przewidziane miejsce na skalowalność, czyli vm001, vm002 itp
- uźywanie małych liter
- unikanie znaków specjalnych
- maksymalna czytelność
- skróty: rg resource group, st storage, vm virtual machine
- środowiska: dev - środowisko developerskie, prod. - produkcyjne, staging -środowisko preprodukcyjne, test, sandbox- służy do testowania i ustabilizownia środowiska infrastrukturalnego, demo - zawiera dane nie produkcyjne, które można usuwać dodawać itp
